# Q42 — 42 over ℂ

Implemented in `q42/`. This note is the design; the module follows it.

```
$ 42q gates ghz "|000>"
ghz |000>
  = 0.707107|000>  +  0.707107|111>

$ 42q matrix gates h
h : qubit <-> qubit
     |0>  [  0.707107   0.707107 ]
     |1>  [  0.707107  -0.707107 ]

$ 42q unitary gates
-- 24/26 unitary, 2 with no single matrix
```

**[`QMANUAL.md`](QMANUAL.md) is the user manual**; this note is the design
rationale behind it.

`run`, `law`, `unitary`, `matrix`, `type`, `show`. `q42/gates.42` is the gate
library, `q42/fib.42` a worked example; `tests/test_q42.py` is 65 tests.

42 is interpreted in **Rel**: matrices over the Boolean semiring 𝔹 = ({0,1}, ∨, ∧).
Q42 is interpreted in **Unitary**: the category of finite-dimensional Hilbert
spaces and unitary maps — matrices over ℂ.

The claim of this note is that the change is smaller than it sounds, that
almost every rule is again *forced* rather than chosen, and that the one thing
42 chose to do without — a type system — stops being optional.

---

## 1. Why this is even possible

Two facts, stacked.

**Rel and Unitary satisfy the same axioms.** Both are dagger compact closed
categories. `inv` in 42 and `U†` in quantum mechanics are the same structural
operation instantiated in different categories — this is the founding
observation of categorical quantum mechanics (Abramsky & Coecke 2004). The
`dagger` in `rel42/core.py` is already `(UV)† = V†U†`.

**42's primitive set is a rig groupoid presentation.** The isomorphisms
witnessing the commutative-semiring structure of `0, 1, +, ×` — precisely the
table in `README.md` — are the generators of **Π**, the universal classical
reversible language of James & Sabry. This was arrived at independently here,
which is some evidence the generating set is the right one.

And Π has a known quantum extension. Carette, Heunen, Kaarsgaard & Sabry
(POPL 2024) prove that a rig groupoid extended with **two maps and three
equations** is a model of quantum computing that is computationally universal
and equationally sound and complete for Clifford, ≤2-qubit Clifford+T, and
Gaussian Clifford+T. They call it √Π.

Q42 is √Π given 42's syntax, values, and evaluator.

---

## 2. What survives, and why

The dividing line is already drawn in `README.md`, which notes that `copy` and
`join` are "the two morphisms that make this Rel rather than a groupoid" and
that `inl`/`inr` are "partial injections, not bijections." That sentence is the
specification for Q42: keep the groupoid, drop the rest.

### Primitives kept — the rig-groupoid core

`id`, `swapsum`, `assocsum`, `unitsum`, `swapprod`, `assocprod`, `unitprod`, `dist`

Over ℂ these are permutation matrices, hence unitary. Nothing to decide.

### Primitives dropped

| | why |
|---|---|
| `zero` | the zero matrix is not unitary |
| `inl`, `inr` | isometries `ℂⁿ → ℂ²ⁿ`, not square, so not unitary |
| `copy` | not unitary — see below |
| `join` | the codiagonal is not unitary; and its converse was the sole source of nondeterminism |

`copy` deserves a precise note, because it is tempting to say "no-cloning" and
move on. The linear extension of `|a⟩ ↦ |a,a⟩` is a perfectly well-defined
isometry `ℂ² → ℂ⁴`. It does **not** violate no-cloning, because it copies only
basis states — in categorical quantum mechanics this map, together with its
adjoint, is a *classical structure*, and Coecke & Pavlović showed those
correspond in Unitary exactly to orthonormal bases. So 42's `copy` is a
measurement basis, not an illegal cloner. It is excluded from Q42 for the
narrower reason that it is not *surjective*, hence not unitary, hence outside
the fragment where `dagger` is an inverse.

### Term constructors dropped: `|` and `^`

This is the part that is genuinely forced, and it is worth stating as a single
fact:

> `Union` and `Star` are exactly the two constructors whose meaning depends on
> addition in the semiring being **idempotent**. ℂ's is not.

`⟦f | g⟧ = ⟦f⟧ + ⟦g⟧`, so `f | f` would denote `2⟦f⟧`, not `⟦f⟧`. And `Star`
is computed by saturation — `while frontier:` in `_apply` — which is a
least-fixed-point over a lattice and has no meaning once `1 + 1 ≠ 1`. Neither
survives the semiring change, and no design judgement is involved.

There is a trap here worth naming. `|` looks like it should be where
superposition comes from, since over ℂ it is literally a sum of vectors. It is
not. Superposition in Q42 comes from applying `v` to a basis state. Keeping `|`
would only buy the ability to write non-unitary formal sums.

### Term constructors kept

`Seq` (`;`), `Sum` (`+`), `Prod` (`*`), `Ref`, and the dagger (`!`).

## 3. The two new primitives

Straight from √Π, with 42's type `1` as the unit `I` and `1+1` as the qubit:

```
omega : 1 → 1        an 8th root of the identity
v     : 1+1 → 1+1    a square root of swapsum
```

subject to three equations, where `S = id + (omega ; omega)` (that is, `id ⊕ ω²`)
and `σ⊕` is `swapsum`:

```
(E1)  omega⁸ = id
(E2)  v² = swapsum
(E3)  v ; S ; v  =  ω² • (S ; v ; S)
```

(E1) and (E2) say only that the square roots exist — no complex numbers are
written. (E3) is the one that does work: without it `omega = id` would be a
consistent choice and the model would not be universal. It says that the
π/2 rotations decompose the same way along `ZXZ` and `XZX`, which is the Euler
decomposition of the Hadamard gate, and it pins the rotation angle to π/2.

In the standard model:

```
⟦omega⟧ = e^{iπ/4}

⟦v⟧ = H · diag(-1, i) · H  =  ½ · [ -1+i   -1-i ]
                                  [ -1-i   -1+i ]
```

and `⟦v⟧² = [[0,1],[1,0]] = X`, as required.

**A cheaper option.** The paper notes that Gaussian Clifford+T is
computationally universal and needs only a *fourth* root of unity — `i` with
`i⁴ = id` in place of `ω⁸ = id`. That is a real design dial: a smaller
generator set, at the cost of the standard Clifford+T presentation and the
`T` gate.

### Scalars need no new primitive, but want sugar

`omega : 1 → 1` is a *scalar*. Applying it to a map on some other type goes
through the unit isomorphism, and that is already expressible:

```
scale(f)  =  unitprod! ; (omega * f) ; unitprod
```

`unitprod! : a → 1×a`, then `omega` acts on the `1` while `f` acts on the `a`,
then back. Denotes `ω · ⟦f⟧`. Correct as written today; unbearable to write
repeatedly. Q42 should have surface sugar for it.

## 4. Semantics: one change to the evaluator

`VSet = Set[Value]` becomes `Vec = Dict[Value, complex]`, and `_apply(t, v)`
returns **the column of ⟦t⟧ at basis index `v`**. Then the existing cases
almost transliterate:

| case | 42 | Q42 |
|---|---|---|
| `Seq` | union over intermediates | sum over intermediates, amplitudes multiplied — matrix product |
| `Sum` | tag with `Inl`/`Inr` | unchanged; amplitudes ride along — direct sum |
| `Prod` | `{Pair(a,b) for a in L for b in R}` | `{Pair(a,b): za*zb for ...}` — tensor product |
| `Ref` | unfold, cache the dagger | unchanged |

The `Prod` case is the same comprehension with a multiplication added. That is
not a coincidence: 42's `Prod` was already the tensor, over the wrong semiring.

**One genuinely new piece of machinery is required.** `_apply` takes a single
`Value`, and a basis value like `Pair(a, b)` is always a product state — so
column-at-a-basis-index stays decomposable and the `Prod` case above is
correct. Entanglement arises when columns are *summed*, which only happens at
the vector level. So Q42 needs a top-level

```
apply_vec(t, ψ)  =  Σ_v  ψ[v] · _apply(t, v)
```

Without it there is no way to ask what a term does to `|+⟩ ⊗ |0⟩`. 42 never
needed this because in Rel, applying a relation pointwise and unioning *is* the
whole story.

## 5. The dagger is unchanged — and now it is an inverse

```python
def dagger(t: Term) -> Term:
    match t:
        case Prim(n, i):  return Prim(n, not i)
        case Ref(n, i):   return Ref(n, not i)
        case Seq(s, u):   return Seq(dagger(u), dagger(s))
        case Sum(s, u):   return Sum(dagger(s), dagger(u))
        case Prod(s, u):  return Prod(dagger(s), dagger(u))
```

Two cases removed, none added, no side conditions. Still total. Still
`dagger(dagger(t)) == t` syntactically. Still eliminable at parse time. The
primitive table now stores adjoints rather than converses — `omega!` is
`e^{-iπ/4}` — and nothing else moves.

But it now buys something strictly stronger. **Every Q42 term is unitary by
construction**, by induction: the generators are unitary; `⊗` and `⊕` of
unitaries are unitary; composition of unitaries is unitary; the adjoint of a
unitary is unitary. There is no well-formedness condition to check and no
proof obligation — the same headline property 42 has, now underwriting a
stronger guarantee.

Which collapses the three-row table in `README.md`:

| Setting | Law | |
|---|---|---|
| Groupoid | `S ; S† = id` | **Q42 — all of it** |
| PInj | `S ; S† ; S = S` | — |
| Rel | `S ⊆ S ; S† ; S` | — |

`README.md` says of the bottom row: *"in Rel, running forward then backward
does not return you to where you started. It returns a set containing where you
started. That is the price of the generality, and the `∈` in the defining law is
where it is paid."*

Q42 does not pay it. `t ; t!` is `id` on the nose.

### The defining law, upgraded

```
42:    x ∈ P(y)              ⟺   y ∈ inv(P)(x)
Q42:   ⟨x| P |y⟩             =   conj( ⟨y| P! |x⟩ )
```

Same law, with `∈` replaced by amplitude equality. It says `⟦P!⟧ = ⟦P⟧†`, and
the `law` command generalises directly: compute the column `P|y⟩`, then for
each `x` with nonzero amplitude, check that the amplitude of `y` in `P!|x⟩` is
its conjugate.

### Recursion is the one soft spot

A terminating `Ref` unfolds to a finite composition of unitaries, so it is
unitary. A non-terminating one is an infinite composition, which need not
converge to anything. Operationally this is 42's `DepthExceeded` again, but the
*semantics* is murkier than it was: in Rel a non-saturating closure still had a
meaning as a set, even an infinite one. Here it may have none.

## 6. Derived gates

In 42's diagrammatic order (`;` is "then"), following √Π's Fig. 8:

```
def x    = swapsum                              -- Pauli X / not
def t    = id + omega                           -- T,  id ⊕ ω
def s    = id + (omega ; omega)                 -- S,  id ⊕ ω²
def z    = id + (omega;omega;omega;omega)       -- Z,  id ⊕ ω⁴
def swap = swapprod                             -- SWAP,  σ⊗

def mat  = dist ; (unitprod + unitprod)         -- (1+1)×A  →  A + A

def h    = scale( x ; s ; v ; s ; x )           -- ω • X∘S∘V∘S∘X
```

Two things to notice.

`s`, `t` and `z` are `Sum` applied with a scalar on the right branch. A phase
gate is *42's existing sum functor with `omega` in one arm*. Nothing was added
to the language to express it.

`h` is `X ∘ S ∘ V ∘ S ∘ X`, which is a palindrome — so for once diagrammatic
and applicative order agree and no reversal is needed.

### Control is `dist`, which is 42's if-then-else

√Π defines `Ctrl m = Mat⁻¹ ∘ (id ⊕ m) ∘ Mat`:

```
ctrl  m  =  mat ; (id + m) ; mat!
nctrl m  =  mat ; (m + id) ; mat!

cx  = ctrl x
cz  = ctrl z
ccx = ctrl cx        -- Toffoli
```

This is exactly the `dist`-based conditional idiom in `MANUAL.md §12.5`. Quantum
controlled gates and 42's if-then-else are the same construct, which is a
pleasant continuity and not something the design had to arrange.

`ctrl` takes a *term* argument, and it is now definable: 42 has parameterised
definitions, so `q42/gates.42` contains

```
def ctrl m = mat ; (id + m) ; mat!
def cx     = ctrl x
def ccx    = ctrl cx
```

and the inferred type is `(a <-> a) -> ((1 + 1) x a <-> (1 + 1) x a)` — control
requires only that the target be an *endo*-relation, because both branches of
`id + m` must meet the `A + A` that `mat` produces. Its adjoint needs no separate
definition: `ctrl! m` is `ctrl m!`.

This replaced twelve hand-instantiations of the same combinator across the two
Q42 libraries with one definition each.

**Should `ctrl` be primitive instead?** Heunen, Kaarsgaard & Lemonnier, *"One rig
to control them all"* (Oct 2025) settles this, and the answer is that it does not
matter: they add **seven** equations for control to a prop of base circuits and
prove the result is the *free rig category* on that prop — so control and rig
structure are interderivable, and their claim is that "rig structure encapsulates
controlled computation, and only controlled computation". 42 builds from the rig
end and gets `ctrl` from `dist`; they build from the control end and get the rig.
Neither is more fundamental.

Two of their observations land directly here. Their Theorem 27 uses the same
generators this file does — `ω⁸ = id`, `V⁴ = id`, `SVS = VSV` — and gets
soundness and completeness for the same three fragments √Π covers, noting that
the rig axioms are *implied by* the control equations; `q42/` has those axioms as
primitives instead. And they record a no-go theorem: there is no circuit
implementing a controlled unitary when the unitary is a **black box**. `ctrl m`
is untroubled because a 42 parameter denotes a *term*, not a value, and is
eliminated by substitution before evaluation — it never receives a black box.

### The classical Toffoli needs no extension at all

`ccx` above uses only `dist`, `swapsum` and `unitprod`. It is writable in **42
today** — it lives in the groupoid row. The reversible-AND that motivated this
whole line of thought, `(a, b, c) → (a, b, c XOR (a AND b))`, is a 42 program:

```
def mat = dist ; (unitprod + unitprod)
def not = swapsum
def cx  = mat ; (id + not) ; mat!
def ccx = mat ; (id + cx)  ; mat!
```

```
$ 42 q42/classical ccx "(R (), (R (), L ()))" --raw
ccx(R (), (R (), L ())) =
  (R (), (R (), R ()))
  -- 1 result

$ 42 law q42/classical ccx "(R (), (R (), L ()))"
ccx(R (), (R (), 0)) has 1 result(s)
  [ok ] (R (), (R (), R ())): inv has 1 preimage(s), input in it
law holds
```

One preimage, not many — `ccx` is a bijection, and the existing interpreter
already computes its exact inverse from the same definition.

Those four definitions live in `q42/classical.42`, which uses only primitives
*both* tables contain, so the same file runs under either interpreter:

```
$ 42q classical ccx "|110>"
ccx |110>
  = |111>
```

`omega` and `v` buy nothing classical. They buy `H`, `S`, `T` — interference.

## 7. Uncomputation

The compute–use–uncompute pattern is conjugation, `P ; Q ; P!`, and in Q42 `P!`
is a genuine inverse, so the pattern is exact rather than merely returning a set
containing where you started. Silq's headline feature is *inferring* where to
insert the uncomputation, so that the programmer never decides. In Q42 it is a
term you write, visible and structural, because the dagger is total and every
term is unitary — a different trade, not a strictly better one.

---

## 8. What Q42 cannot do

**No measurement, and no state preparation.** √Π explicitly does not consider
these. Every Q42 term is a unitary on a fixed space; you cannot inject a fresh
`|0⟩`, because `A → (1+1) ⊗ A` doubles the dimension and is not an iso —
`inl`/`inr` were dropped for exactly this reason. So Q42 computes the unitary,
never the outcome distribution: it cannot express "run Grover and read the
answer." Inputs are supplied by the runner, as they already are on 42's command
line.

The route to fixing this is known and is a *further layer*, not a patch:
Carette, Heunen, Kaarsgaard & Sabry, *"The Quantum Effect: A Recipe for
QuantumPi"*, builds quantum computing as two copies of Π glued by the
complementarity equations of classical structures, using Hughes' arrows, with
measurement added as an effect on top. Q42 as specified here is the pure
unitary core that such a layer would sit on.

**No library.** `arith.42`, `strings.42`, `cipher.42` and most of `prelude.42`
use `copy` and `join` and do not port. Q42 is not a superset of 42; it is a
different language over a shared core. Π-style programming without the diagonal
is more verbose, and the `dist`-conditional idiom carries most of the weight.

**Exponential cost.** A term on n qubits is a 2ⁿ×2ⁿ matrix and running on a
superposition is dense simulation. 42's backward runs were already exponential;
this is not new, but it is now unavoidable rather than a consequence of
unpruned search.

**A display problem, slightly worse than 42's.** `|1⟩` is `Inr(())` while the
Peano `1` is `Inr(Inl(()))`, so the existing nat sugar will mis-render qubits.
Q42 needs a bit convention in the printer.

## 9. The finding that matters: types stop being optional

`README.md` lists "No type system" under honest limitations and calls types
"the obvious next layer." For 42 that is fair — an ill-shaped application
yields `∅`, and in Rel the empty relation is a real morphism, so the answer is
*semantically correct* even when it reflects a typo.

Q42 does not get off so lightly. An ill-shaped application yields the **zero
column**, and the zero matrix is not unitary. So a shape mismatch does not
merely give an unhelpful answer — it silently produces a term whose denotation
is outside the intended semantics, breaking the unitarity-by-construction
guarantee of §5, which is the entire point of the design.

Applying `omega` to a `Pair` is enough to do it.

So: 42 can defer types indefinitely. **Q42 cannot be built without them.**
That is the single largest piece of work this extension implies, and it is
mostly work that 42 wants done anyway — it would also settle the `0`/`[]`
collision.

## 10. Open design questions

1. **Separate language or checked fragment of 42?** *Settled: separate, and
   built.* The primitive sets differ in both directions — decisively, since (E2)
   has **no model at all** over 𝔹 (of all 16 boolean 2×2 matrices, none squares
   to `X`; a square root of an invertible boolean matrix must be a permutation
   matrix, and neither permutation on two points squares to the swap). So a
   semiring parameter could not unify them: it would need a well-formedness
   predicate on `Term`, which is the one thing this design refuses.

   What that turned out *not* to mean is forking much. `q42/` shares `Value`,
   `Term`, `dagger`, the parser and the whole type-inference engine, and forks
   only the primitive table and the evaluator. Two one-line injections made it
   possible: `_Parser` takes the primitive *names* and `Inference` takes the
   primitive *schemes*. `tests/test_q42.py::TestSharedWithRel42` asserts the
   sharing is real — `q42.dagger is rel42.dagger`, and importing `q42` does not
   perturb 42's tables.

2. **Equational or denotational?** √Π's point is that you can prove a great deal
   without ever writing a complex number: `S ; S = Z` follows from rig coherence
   plus (E1). Matrices are for *running*. Both are wanted, and they map onto the
   two commands that already exist: `run` denotational, `law` equational.

3. **ω⁸ or i⁴?** Gaussian Clifford+T is universal with a fourth root of unity.
   Fewer generators against a less standard gate set.

4. **`ctrl` primitive, derived, or sugar?** Derived works today (§6). Making it
   a term former needs parameterised definitions, which 42 has so far done
   without.

5. **Types.** Not really an open question. See §9.

## Appendix: spike results

*Superseded by `q42/` and `tests/test_q42.py` (57 tests), which check all of
this and more against the real module. Kept because it is the evidence this note
was written from.*

`spike/q42_spike.py` — a ~150-line throwaway evaluator over
`Dict[Value, complex]`, reusing 42's parser, `Value` universe and `dagger`
**verbatim**. `python3 spike/q42_spike.py`; all 21 checks pass.

Confirming the model (Prop. 6 of √Π), with `ω = e^{iπ/4}` and the `V` of §3:

```
[ok] E1   omega^8 = id
[ok] E2   v ; v = swapsum
[ok] E3   v;S;v = omega^2 . (S;v;S)
```

Confirming §6's derived gates — note `h` comes out as *exactly*
`(1/√2)[[1,1],[1,-1]]`, with no residual phase, so the `ω •` scaling in
`H = ω • X∘S∘V∘S∘X` is exactly right and not merely right up to phase:

```
h = [ 0.7071   0.7071 ]      h ; h = id
    [ 0.7071  -0.7071 ]

[ok] s ; s = z            [ok] h ; x ; h = z       (Lemma 11)
[ok] t ; t = s            [ok] h ; z ; h = x       (Lemma 11)
```

Confirming §5 — `t ; t! = id` for every definition, computed with **rel42's own
unmodified `dagger`**: `x`, `t`, `s`, `z`, `v`, `omega`, `h`, `mat`, `cx`,
`ccx`, `bell`. Eleven for eleven.

Confirming §6's claim that the classical gates stay classical:

```
cx : 00->00  01->01  10->11  11->10
ccx: 000->000 001->001 010->010 011->011 100->100 101->101 110->111 111->110
```

And the thing 𝔹 cannot do at all:

```
h|0>          = 0.7071|0> + 0.7071|1>
h(h|0>)       = 1.0000|0>                  <- the |1> paths cancelled
bell|00>      = 0.7071|00> + 0.7071|11>
cx(|+> (x) |0>) = 0.7071|00> + 0.7071|11>  <- needed apply_vec; not a product state
```

Two findings for the module question -- question 1 of section 10 -- both
supporting the fork:

- The fork is small and well-localised. The new evaluator is ~40 lines and the
  primitive table ~70; against that, `syntax.py` (448 lines), the `Value`
  universe, the `Term` type and `dagger` were reused unchanged. `Union` and
  `Star` raise rather than being interpreted, which is §2 enforced rather than
  merely asserted.
- **The parser needs one parameter.** `syntax.py:161` reads
  `Prim(text) if text in PRIMS else Ref(text)`, so the primitive-name table is
  baked in — the spike had to register `omega` and `v` into `rel42.core.PRIMS`
  to get them tagged as primitives. A shared parser wants that set injected.
